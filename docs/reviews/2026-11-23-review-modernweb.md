## Gaps

### High
1. **Single 939 kB JS chunk (281 kB gzip), Vite warns >500 kB** (build output; vite.config.js has no splitting). All ~every lesson/theory/guide module is in the entry. Guide: performance (LCP/INP, from knowledge). Fix: `React.lazy(() => import(...))` per route (LessonPage/GuidePage) and lazy lesson registry (src/lessons) + `<Suspense>`; optionally `manualChunks` for react/router. Keep a fixed-height fallback to avoid CLS.
2. **Render-blocking third-party font CSS, no stable fallback** (index.html:9-11). Google Fonts stylesheet is render-blocking, 5 weights (400-800), the monospace fallback stack metrics differ from JetBrains Mono, so the swap shifts layout (CLS). Also leaks IP to Google and needs a CSP exception. Guides: visually-stable-font-fallbacks, optimize-preload-priority. Fix: self-host WOFF2 (variable font, one file, `font-display: swap`), `<link rel=preload as=font type=font/woff2 crossorigin>`, add `font-size-adjust: from-font` (or `ch-width from-font`) on body (app.css:5 / tokens.css:7), drop unused weights.
3. **No route announcement / title / focus management on hash navigation** (App.tsx routes; no `document.title` anywhere (grep empty); LessonPage.tsx:97 and GuidePage.tsx:175 only `scrollTo` on narrow). Screen-reader users get no cue after link click; browser history/tab all say "Tracepoint". Guides: accessibility, same-document-transitions (from search). Fix: per-route `document.title = "<lesson> · Step n - Tracepoint"`; on route change move focus to the `<h1>` (tabIndex=-1) or a polite live region; optionally `document.startViewTransition` for step/lesson swaps gated by reduced-motion.

### Medium
4. **No security headers / vercel.json** (project root has none). No CSP, no `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors`/`X-Frame-Options`, `Permissions-Policy`. Guide: security (from knowledge). Fix: vercel.json `headers` with CSP `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' [+ fonts.googleapis.com if not self-hosted]; font-src 'self' [fonts.gstatic.com]; img-src 'self' data:; frame-ancestors 'none'; base-uri 'none'; object-src 'none'`, plus the others. Self-hosting fonts (gap 2) lets CSP drop third-party origins. Also add long-cache `immutable` for /assets/* (Vercel does by default for hashed assets).
5. **Search dialog is not a proper combobox/listbox** (SearchDialog.tsx:56-66). `aria-selected` on `<button>` is invalid (aria-selected not allowed on button), input has no `role=combobox`, `aria-controls`, `aria-activedescendant`; arrow-key selection is invisible to screen readers; no result-count live region. Guide: accessibility (from knowledge). Fix: `<input role="combobox" aria-expanded aria-controls="s-list" aria-activedescendant={id}>`, `<ul role="listbox">`, `<li role="option" aria-selected>` (buttons -> options), `aria-disabled` for "soon"; `role=status` "N results". Also scroll selected into view (list max-height 50vh, app.css:329).
6. **Slider relies on a document-level key handler** (LessonPage.tsx:253; useKeyboard.ts). Works for arrows/Home/End, but PageUp/PageDown (±10%) missing, and the slider is unusable if the handler is `enabled=false` or inside a dialog; no `aria-orientation` (default horizontal OK). Guide: slider (recommends native `<input type=range>` with CSS styling; custom role=slider is acceptable only with full APG keyboard support). Fix: add `onKeyDown` on the slider element (Arrow/Home/End/PageUp/PageDown, `stopPropagation`) or migrate to `<input type=range min=1 max=N>` + `aria-valuetext`, keeping tick overlay; get free touch/keyboard/AT behaviour. Also hover "peek" (`setPeek`) is mouse-only; ok.
7. **Light dismiss uses hand-rolled click handler** (SearchDialog.tsx:51-52, CourseDrawer.tsx:36-40). Guide light-dismiss-a-dialog: use `closedby="any"` (Chrome 134, Firefox 141; not Safari) with the click fallback only when `!('closedBy' in HTMLDialogElement.prototype)`. Current handler is correct but doesn't distinguish pointer-down-inside/up-outside (drag-select in the search input that ends on the backdrop closes the dialog). Fix: add `closedby="any"` (React: spread `{...({closedby:"any"} as any)}`), guard the fallback with the feature check and rect test per guide. Drawer: the `a[href]` auto-close is fine.
8. **Missing head metadata** (index.html). No `theme-color` (two media variants for light/dark), no favicon (browser requests /favicon.ico and 404s; there is no `public/` dir), no `<link rel=manifest>`/apple-touch-icon, no `og:` tags, no `<noscript>` message (blank page without JS). Fix: add inline SVG favicon, `<meta name=theme-color media="(prefers-color-scheme: light)" content="#f3efe9">` and a dark twin (update with theme toggle via JS since data-theme can override media), `<noscript>`.
9. **Touch target sizes** `.icon-btn` 32x32 (app.css:32), `.btn` ~30px tall, search `.search-btn` 32px on mobile (app.css:438). WCAG 2.2 AA 2.5.8 needs 24px (met), but 44px is preferable on `(pointer: coarse)`. Fix: `@media (pointer: coarse){.icon-btn{min-width:44px;min-height:44px}}`.

### Low
10. **legacy-scan array-copy findings** (13 `[...x].sort()` / `.slice().reverse()`): valid only if lib is raised; tsconfig `lib`/`target` is ES2020 (tsconfig.json), so toSorted/toReversed would not typecheck. Per rubric dropWhen (config older than ES2023) they are dropped now. Optional: bump `lib` to ES2023 and apply; Vite's default build target does not polyfill, support is Chrome 110/Safari 16.
11. `100vw`-based sizing (`min(520px, calc(100vw - 32px))` app.css:326, `88vw` :130) includes scrollbar width; prefer `100dvw`/`inline-size` units. Check any `100vh` usage on mobile for `dvh` (none found by grep for 100vh).
12. Prefer logical properties (`inline-size`, `margin-inline`) for RTL readiness; app is LTR English so cosmetic.
13. Hover-only previews: scrub peek works on mouse only (LessonPage.tsx:167); fine, but keyboard users get valuetext instead. OK.
14. Search shortcut Ctrl/Cmd+K toggles (App.tsx:~49): ensure it is discoverable (button has label/kbd hint) and that single-key shortcuts R/F/Space (useKeyboard.ts) satisfy WCAG 2.1.4 (Character Key Shortcuts): they are active whenever focus is not in an input. Provide a way to turn off/remap, or only active when the slider/stage region is focused. (Guide: accessibility, from knowledge.) Could be Medium for strict WCAG AA.
15. Popover API / `:has()` not needed; no dropdown menus found, so no gap. Anchor positioning could replace the manual `--x` scrub tooltip offset (app.css:212) but current approach works.
