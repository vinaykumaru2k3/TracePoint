# Tracepoint

Interactive, step-through lessons for learning data structures and algorithms, styled like a debugger. The name comes from the debugger tracepoint: a spot where you record what happened. Here the learner records every operation, one step at a time.

## Current state (milestone M5: DP and advanced)

React 18 + Vite 5 + TypeScript (strict), react-router-dom 6 `HashRouter`, Vitest. Font: JetBrains Mono for everything (`--font`, with `--mono` pointing at it), self-hosted: `public/fonts/jetbrains-mono-latin-wght.woff2` (latin subset, variable weight, from the `@fontsource-variable/jetbrains-mono` devDependency; licence in `public/fonts/OFL.txt`), declared by `@font-face` at the top of `tokens.css` with `font-display: swap` and preloaded in `index.html` (`crossorigin`; the URL must match in both). The greek and latin-ext faces (`jetbrains-mono-greek-wght.woff2`, `jetbrains-mono-latin-ext-wght.woff2`) are not preloaded: `unicode-range` loads them on demand, and only the latin face is preloaded. `body` sets `font-size-adjust: from-font` so fallback text keeps the same size during the swap. No Google Fonts requests. Head and headers: `index.html` has the favicon (`public/favicon.svg`, the ember dot), `public/manifest.webmanifest`, two `theme-color` metas and a `noscript` line; `useTheme` keeps the metas in step with the resolved theme (`themeMetaColors`). `vercel.json` sets the security headers (strict CSP with no third-party origins, nosniff, DENY, COOP, Permissions-Policy; HSTS is left to Vercel) and `vite preview` serves the same headers, the dev server does not. `head.test.ts` guards them. Commands: `npm run dev`, `npm run typecheck`, `npm test`, `npm run build` (typecheck + vite build, output `dist/`, Vercel-ready).

Lessons done (M0–M5): all 10 sections, 49 lessons. Foundations: big-o-by-counting, arrays, strings, two-pointers, sliding-window, prefix-sums. Linear: stack, queue, deque, singly/doubly linked list, fast-and-slow-pointers. Hashing: hash-table-chaining, open-addressing, frequency-map-and-two-sum. Recursion: call-stack, backtracking, n-queens. Searching and sorting: linear-search, binary-search, bubble-sort, selection-sort, insertion-sort, merge-sort, quick-sort, counting-sort. Trees: tree-traversals, bst, avl-rotations, binary-heap, heap-sort. Tries: trie, autocomplete. Graphs: representations, bfs, dfs, topological-sort, dijkstra, union-find, kruskal-and-prim. Dynamic programming: fibonacci, climbing-stairs, coin-change, knapsack, lcs, edit-distance. Advanced: bit-manipulation, greedy-intervals, segment-tree. Every lesson in the curriculum (`src/curriculum.ts`) is live. `COURSE` there is the `DSA` root of the explorer tree, and `folderName()` makes folder names like `01-foundations/`.

The theory layer is in too: ten folder guides (one per section) and a theory tab for all 49 lessons.

Roadmap: M0 platform → M1 … M5 DP/advanced (done), one branch and PR each. Cycle 2: predict-the-next-step, quizzes, worked case studies per lesson.

- `engine/` `types.ts` (the lesson contract), `anchors.ts`, `usePlayer.ts` (autoplay over a URL-owned index).
- `hooks/` `useKeyboard` (`onStep` fires on a key step), `useTheme`, `useProgress`, `useLang`, `useStoredFlag` (a remembered boolean: "1" true, "0" false, else the fallback; every on/off flag goes through it, and every instance stays in sync in the same tab through a `tracepoint-flag` event; `resetTips()` clears the tip, keys-seen and intro flags, used by "Show tips again" in the How to use popover), `useTip` (the first-visit trace tip). All persisted in localStorage (`tracepoint-*`) inside try/catch. Flag keys: `tracepoint-run-open`, `tracepoint-memory`, `tracepoint-keys-seen`, `tracepoint-tip-seen`, `tracepoint-intro-hidden`, `tracepoint-whole`.
- `iso/` isometric SVG primitives: `project.ts` (2:1 projection), `IsoScene`, `IsoBlock`/`IsoPlate`, `IsoPointer`, `Blocks` + `useGhosts` (enter/leave animation), `fitBox` for a fallback viewBox. `SceneFit` (memoised, so a step change or hover does not redraw it) draws every step of the run off-screen, reports each step's bounds, then renders nothing once measured (after fonts are ready) until `steps` or `Scene` change (`fitScenes`); `IsoScene` runs a camera (`camera.ts`, `follow`) through `CameraContext` that glides to each step: it holds the shot while the drawing fits, pans just enough when it does not, zooms out when the drawing outgrows the stage, and zooms back in only for a real gain (never past `MAX_SCALE`). On the lesson stage a `ZoomContext` lens (`floor` 0.85, `read` 1) keeps it readable: when fitting everything would drop under the floor, it reads at up to 1× on the step's focus (active, compare and swap cells, lit edges, live pointers, windows, measured by `SceneFit`; the focus always fits whole, and it crops only for a 1.2× gain or more), shows a chevron on each edge the drawing runs past, and offers a Show all toggle (F, stored in `tracepoint-whole`). Walkthroughs set no lens and fit everything. The grid floor is drawn in scene units inside the SVG, so it moves with the camera. Reusable scene pieces: `CellRow` (`rowFrame`, indexed cells, null draws stale), `LinkedNodes` (`listFrame`, next/prev links, back links curve), `Buckets` (`bucketFrame`), `FrameStack` (call frames, newest on top).
- `lessons/<id>/` `generate.ts` (pure), `Scene.tsx`, `index.ts` (`defineLesson`), `generate.test.ts`, `theory.ts`, `code/Main.java|main.py|main.cpp`. Lessons load on demand, one chunk each: `meta.ts` is the light registry (`LESSON_META`, `META_BY_ID`, `DEFAULT_LESSON`: id, title, section and default-run step count as literal data, guarded by `meta.test.ts`), `load.tsx` is the loader (`loadLesson`, `peekLesson`, `useLesson`, `LazyLesson`, plus `primeLessons`/`clearLessons` for tests). App code reads meta and loads through `load.tsx`; it never imports `lessons/index.ts`, which eagerly imports all 49 and is for tests only (`src/test/setup.ts` primes the cache from it). `LessonPage` shows a `lesson-loading` main (`aria-busy`) and reports no progress until the chunk arrives. `parseOps.ts` parses the "type your own values" input. `sortkit.ts` (`SortState`, `SortTrace` snapshot builder whose `finish()` adds the closing sorted step, `sortMetrics`, `sortMemory`) and `SortScene.tsx` (array row plus an optional aux row such as tmp, key or count) are shared by every sort. `treekit.ts` holds the tree helpers: BST and AVL builders, `leafCols` layout, `heapView`/`heapFrame` (a heap as both tree and array), `levelsFor`, `nodeMemory`, and the trie helpers (`trieChild`, `trieAdd`, `trieSize`, `trieLayout`, `trieMemory`). `TreeScene.tsx` draws any of them through `iso/TreeNodes.tsx` (nodes, edges, tags and pointers). `graphkit.ts` holds the graph helpers: `parseGraph` (edges like `A-B 4`, `start C`, directed or weighted), `adjacency` (neighbours in insertion order, an undirected edge on both ends), `ringLayout` and `forestLayout` (union-find trees), `graphView`, `adjMemory`, `distText`, `ekey`. `GraphScene.tsx` draws them through `iso/GraphNodes.tsx` (nodes, edges with state, weights and arrows) with an optional labelled strip under the graph (queue, order, heap, parent array). Union-find is its own lesson and Kruskal reuses its idea. `dpkit.ts` holds the DP helpers: `DPState` (a 1D row or a 2D grid of `Cell`), `blankGrid(rows, cols)` (all `v: null`, drawn stale), `paint(grid, cells, state)` (a copy with those `[r, c]` cells set), `tableMemory` (a `layout: "table"` memory view: one monospaced line per row, columns padded and named from `colHead`, `#` for an empty plate and `_` for not computed), and `parseInts` / `parseWords` that reject bad input with a sentence that says why. `DPScene.tsx` draws a 1D table (`CellRow`) or a 2D table (`iso/GridTable.tsx`: `IsoPlate` cells with row and column headers, optional pointers, `gridFrame` for `SceneFit`) with an optional labelled strip under it (call stack, coins, chosen items). DP cell states: `active` the cell being written, `compare` the cells it reads, `found` the answer and the traceback path, `stale` not computed yet, `default` computed. `testkit.ts` has `run`, `at` (no `Array.at` in the TS lib) and `rets` for generator tests.
- `theory/` the reading layer. `types.ts` (`LessonTheory`, `Guide`), `check.ts` (`checkText`, `checkGuide`, `checkTheory`), `inline.tsx` (`Rich`, plain markup), `guides/<section>.ts` (one guide per section) and `index.ts` (`GUIDES`). `growth.ts` (`LADDER`, `growthRank` parses a cost like `O(n log n)` into its rung; `O(deg)` ranks as O(n) and `O(α(n))` as O(1)), `Meter.tsx` (`GrowthMeter`, `Cost`: a cost with its 7-rung meter), `GrowthChart.tsx` (the growth curves under a guide's cheat sheet) and `useInk.ts` (draws the reading marks as they scroll past a reading line). Each theory has `shots`, one 1-based trace step of the default run per How-it-works step; `app/Walkthrough.tsx` draws that step's scene beside the list.
- `design/` `tokens.css`, `ui.tsx`. `app.css` is the layout.

## How a lesson works

`generate(input)` returns `Step[]`, problem step first and recap last. A step holds a title, text, key idea, op, `anchors`, `notes`, and a `state` that only the lesson's `Scene` understands. The renderer draws one snapshot, so going back is free.

Code is shown in Java, Python and C++. Each source file tags lines with `// @a name` (or `# @a name`). Steps name anchors, never line numbers, so highlights follow the selected language tab. Tests check that every anchor a step uses exists in all three languages.

### Theory layer

Every lesson has a theory, and every section with a live lesson has a guide. Routes: `#/` is the Foundations guide, `#/guide/:sectionId` is a folder guide (the `README.md` entry in the explorer), `#/:lessonId/learn` is the lesson's theory tab. The writing rules are in `docs/specs/theory-layer.md`: write for a beginner, define a word before you use it, keep sentences to 25 words and paragraphs to 80, never talk down, use no exclamation marks, and mark up text only with `code`, `**bold**`, `~~wrong form~~` (pitfalls) and `[[links]]`. The spec has the full list of banned words. `checkText` tests the mechanical ones. In the explorer, an unstarted lesson links to its theory tab. Search finds guides as "<Section> guide". Guides and theory tabs do not count toward progress.

### Add a lesson

1. Add it to `curriculum.ts` if it is not there.
2. Create `src/lessons/<id>/` (the folder name must equal the lesson id: the loader keys chunks by folder) with `generate.ts`, `Scene.tsx`, the three code files, `theory.ts` (a `LessonTheory`, set as `theory` in `index.ts`), `index.ts`, and a test.
3. If the lesson opens a new section, add a guide for it in `src/theory/guides/` and to `GUIDES`.
4. Register it in `src/lessons/index.ts` (for tests) and add its row to `src/lessons/meta.ts` (id, title, section, default-run `steps`; `meta.test.ts` fails if a value is off). `lessons.test.ts` then checks parse defaults, anchors, learn checklist and curriculum membership.

## Design rules

Tracepoint looks like a debugger in warm graphite: espresso-tinted neutrals (not beige paper), hairline borders (`--line`), no card shadows. The only shadow is `--float-shadow`, on popovers and dialogs. `--signal` is an ember orange and marks things only, never text: the logo dot, the current-lesson bar and the timeline playhead. `--done` (green) is completion: the progress rings, the done checks and the progress bar. The current state is inverted with `--inv-bg` / `--inv-fg`: the primary button and the selected code tab. `--radius` is 6px.

Type is JetBrains Mono everywhere (`--font`; `--mono` is the same stack and stays as the token for code, values, ops, paths, counts, kbd and scene labels). Type has four tiers, tokens in `tokens.css`: `--fs-title` 20px (the explanation h2, the intro h2), `--fs-content` 15px at `--lh-content` 1.6 (explanation body, the `watch` note, intro copy, mini-trace title), `--fs-chrome` 12px (toolbars, labels, the metrics line: one muted line of `label value · label value` with the values in ink, the memory head, form hints, the run-fold summary, the tip) and `--fs-micro` 11px (only indices, kbd caps, "soon" tags and the phone metric labels). Nothing is under 11px; ligatures off.

The lesson page is flat panes, each with a `.pane-title` bar: EXPLORER (the course tree), TRACE (the explanation) and CODE. The explorer is a tree under `DSA/` with folders like `01-foundations/`; the current lesson has a 2px signal bar on `--surface-2`. Each lesson shows its status as a mark: an empty ring (not started), a ring that fills with the share of steps reached (in progress), or a closed green ring with a stroked check inside (complete), and the lesson name goes muted. A lesson finished in this session closes its ring and draws its check once (not with reduced motion). A folder shows `done/live` completed lessons, with a green check before it once every live lesson in it is complete; empty folders say `soon`. The lesson head is a mono path crumb (`dsa / <section> / <lesson>`), the h1 and one meta line (`N min · level · N steps`). On the trace tab the head is one slim bar (h1, meta and the view tabs, crumb and subtitle hidden) so the stage gets the height. On desktop the input form is one row (its hint shows only while editing) and sits in a `<details class="run-fold">` (summary "Try your own input · <label>") that is folded by default, remembered in `tracepoint-run-open`, and forced open on a custom run or a link error; the memory strip is a `<details>` folded by default (`tracepoint-memory`, "1" = open). Below the stage is the TIMELINE, a scrubber: one track with one tick per step in its kind's colour (`kindColor` in `design/ui.tsx`). Ticks grow with state (future, seen, past, hovered), the walked stretch is filled in ink up to the playhead, and an ember knob carries an inverted label with the step number and short name: the step's `short`, else its op, else its kind when one op names 40% or more of the run (so `bfs(A)` on every step never repeats). That rule is `stepName` in `engine/stepName.ts`, shared by the scrubber, Next and the phone step bar. A step's `short` is 24 characters or fewer, never a bare coordinate (`i3 j3`, `back i2`: `COORD` there), and grid and graph lessons set one on every step; a watch note (`idea`) is 160 characters or fewer. `lessons.test.ts` checks all three over every preset. The label is clamped to the track. The header reads `Step N of M · title`; hovering the track previews `Jump to step N · title` there without moving the playhead. The track is one `role="slider"` (aria-valuetext `Step N of M: title`); click or drag scrubs with pointer capture (`touch-action: pan-y`), and the slider handles its own keys (arrows, Home/End, and PageUp/PageDown by a tenth of the run) then stops the event, so the global keyboard handler never steps twice. It always fits its width, however long the run. The TRACE pane opens with `#NN op`, shows the key idea as a `watch` block, then Back / `Next: <stop name>` (the next step's rail name; the phone step bar just says Next) and the key legend (chrome tier, muted; the step sentence is `.explain .say`, the only 15px paragraph there; the legend wraps only between key and label pairs), which shows until the first keyboard step (`tracepoint-keys-seen`; it stays for that visit, so the layout does not jump) and is then replaced by one muted line, "Keys: see ? (How to use) in the top bar"; both are hidden on `hover: none`. The kind chip carries a `title` that says what the kind means (`KIND_MEANING`). The phone step bar names the step with the same rail name as the scrubber and Next. The cue pulse on Next runs only on step 1 while not playing. Speed reads `Speed N×` with its width reserved, and Show all is always rendered, disabled when nothing is cropped. A first-visit tip sits under the scrubber (`useTip`): shown on steps 1 and 2, marked seen (`tracepoint-tip-seen`) on dismiss or on reaching step 3, with touch wording on `pointer: coarse`. A "Skip to step controls" link (`SkipLink`, first in the app) appears on trace routes only and focuses the first enabled button of `#step-controls` (the explanation nav) or, on a phone, of `[data-step-controls]` (the step bar). On `#/` an `Intro` sits above the Foundations guide: a heading, a mini-trace of stack steps 1 to 3 played by hand, Start the course and Hide (`tracepoint-intro-hidden`, focus moves to the page h1); it is gone once any progress exists or after Hide. Its two columns switch on the intro's own width (container query, 720px), and while it shows the hero button is secondary, so there is one primary way in. A run submitted from the run form keeps the form open. The checklist reads `Checkpoints · n/m hit`. The top nav is a signal dot, a lowercase mono "tracepoint" and underline editor tabs.

Scenes are flat faces with 1px outlines and warm neutral slabs (`--slab-*`) on a dot grid floor. The floor is drawn in scene units, so it is locked to the camera. The footprint is a dashed 1px outline, with no fill. Pointers are flat flags. `IsoScene` sets `--px` (scene units per screen pixel, `sceneScale`) on its svg; tag text (`.tag-body`) and grid headers scale by `max(1, var(--px))`, so they keep their screen size when the camera zooms out. Below 1120px the stage is `clamp(260px, 45vh, 540px)` tall so the step sentence shows on the first screen at 1024×768. Colour appears only for state (amber active, green found, blue compare). The one exception is identity: each explorer folder has a hue (`--sec-01` … `--sec-10`) that fills its icon (the outline stays ink), tints the open folder's indent guide and the guide crumb swatch; these are decorative fills only and never carry text.

Light and dark themes via tokens (`prefers-color-scheme` plus `data-theme`); every colour, including scene state fills (`--st-*`) and syntax (`--syn-*`), is a token with a dark value, and no raw colours live outside `tokens.css` (except the luminance-mask white in `IsoScene`). Text holds 4.5:1 and is never below 11px, including muted text on `--surface-2` and the inverted pairs. Icons come from `Icon` in `design/ui.tsx`, never unicode glyphs. No card inside a card. Layout: top nav, then EXPLORER | lesson (head, stage = controls bar / drawing / legend bar, step timeline, input, memory) | TRACE + CODE + Checkpoints (the right column). On desktop the EXPLORER column folds to a 44px strip holding only its toggle (`SideCol`, `aria-expanded`, the grid column width animates, not with reduced motion): it starts folded on the trace tab so the stage gets the width and open on guides and theory tabs, and a manual choice is remembered per kind of page in `tracepoint-explorer` (`hooks/useExplorer`). Below 1120px wide or 680px tall: one column, lesson first (head, stage, explanation, timeline, code, input, memory, checkpoints), the course tree in a drawer, the page scrolls. At 560px and below the step's sentence must sit on the first screen above the step bar: live values share one line, the drawing is 240px, the colour key folds to its swatches, the returns box is one line, the trace head drops its meta line, and the explanation drops its pane title, `#NN op` head, Back/Next and key legend, which the step bar repeats, and Practice and Quiz "soon" tabs are hidden (their soon tags show above 560px). Guide and theory pages are reading surfaces that use the full width: body prose is 14px with line height 1.65, each paragraph keeps a measure of about 72 characters, and above 820px of content width related parts sit side by side in bands (core idea beside analogy and prerequisites, definition beside analogy, operations beside at a glance, worked example beside pitfalls; tips, the gallery and key terms go to columns; case studies become rows). Each part sits under a `.pane-title` label, and tables use hairline rules. A guide opens on a hero: crumb, a 34px h1, the tagline, a primary button that starts or continues the first unfinished lesson, lesson and completion counts, and (from 680px) the first lesson's scene in a well tinted with the section hue. Cost tables are heatmaps on hairline rows: each cost sits in a chip tinted by its growth class (`--heat-found` / `--heat-active` / `--heat-swap`) with its meter pinned to the chip's right edge, a cost never breaks inside itself, and a cheat-sheet row name is a row header in ink with any trailing `(qualifier)` on a muted line below. They draw with the lesson's own pictures: How it works is a walkthrough, with numbered steps beside the lesson's scene at that step (a `--surface-2` well that is sticky, with Previous/Next and a link into the trace). Every cost carries a growth meter, 7 rungs filled in the state colour for its class (green up to O(n), amber O(n log n), red beyond). A guide's cheat sheet is followed by the growth chart, which inks the classes it names. Use it when / Avoid it when are green check and red close marks, pitfalls and tips read like a compiler's warning list (hairline rows, an amber warn badge, the first sentence set as an ink headline with the rest muted, and a wrong form on a red `--wrong-chip`, with no strike line), the analogy is a `--surface-2` well with a bulb, the worked example has a line-number gutter, and Lessons here shows each lesson's scene as a thumbnail. Reading marks: bold is a highlighter band in light (`--mark`, amber; `--mark-no`, red, in Avoid it when) and, in dark, a faint wash with a crisp 2px edge (`--mark-edge`), like an editor's find match; it is drawn by default, and `useInk` draws the bands below the fold as they cross 85% of the viewport. Respect `prefers-reduced-motion`. Accessibility: `document.title` names the lesson and step, tab or guide (`hooks/usePage`); a new page (not a new step) focuses its h1; one visually hidden live region says `Step N of M. Title. Text`, empty while playing; the stage is described per step from the memory strip (`aria-describedby="scene-state"`). Search is a combobox over a listbox (`aria-activedescendant` follows the highlighted option; with no results `aria-controls` is dropped; a debounced `role="status"` line says the result count). On touch screens (`pointer: coarse`) every control is at least 44px, set with logical `min-inline-size` / `min-block-size`. A guide's thumbnails and hero scene load their lesson chunk on demand, each behind its own `ErrorBoundary` that falls back to an empty `aria-hidden` placeholder, so one failed chunk does not take the guide down. While a lesson page's chunk loads, the page frame (course tree, centre at the stage's height, `aria-busy`) stays. Routes and the scene sit inside `ErrorBoundary`, so a render error shows a message, not a blank app. Draw order in scenes follows array order (list back to front); no depth sorting.
